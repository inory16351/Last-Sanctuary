## 🔒 §0. 문서 수정 규약 — 이 문서를 여는 모든 사람·에이전트가 먼저 읽을 것

이 문서는 참고 메모가 아니라 **두 브랜치가 서로를 깨뜨리지 않기 위해 합의한 구속력 있는 규약**이다.
**임의 수정·삭제·완화 금지.** 갱신이 필요하면 아래 프롬프트를 그대로 읽고 따를 것.

> ### 갱신 프롬프트 (이 문서를 고치려는 에이전트는 그대로 따를 것)
>
> 너는 지금 `프로토 브렌치 준수사항.md` 를 갱신하려 한다. 이 문서는 `main` 으로의 최종 머지를 **충돌 0으로** 끝내기 위한 제약 조건 명세다. 아래를 전부 지켜야 갱신한 것으로 인정된다.
>
> 1. **기존 제약을 지우거나 약화시키지 말 것.** 제약이 현실과 맞지 않으면 삭제가 아니라 "§N 은 이런 이유로 이렇게 바뀐다"를 **새 항목으로 추가**하고 원래 항목에 링크한다. (`진행상황.md` 0절 3번과 같은 원칙)
> 2. **추가만 한다.** 본문의 § 번호와 순서를 재배치하지 말 것 — 짝 문서와 `머지 계획.md` 가 § 번호로 이 문서를 인용하고 있다.
> 3. **§2(파일 소유권) · §3(씬 접근 금지)은 단독으로 바꿀 수 없다.** 변경은 **유저의 명시적 승인 + 양쪽 브랜치 문서 동시 갱신**이 있어야만 유효하다. 한쪽만 바꾸면 머지가 깨진다.
> 4. 갱신할 때마다 맨 아래 **§12 갱신 이력**에 (날짜 / 브랜치 / 무엇을 / 왜) 한 줄을 남긴다. 이력 없는 변경은 무효로 보고 되돌린다.
> 5. **작업 방향을 유지할 것.** 이 문서의 목적은 "각자 빠르게 만들기"가 아니라 **"머지 시점에 충돌 없이 합쳐지기"** 이고, 그 수단은 **① 파일 단위 단독 소유 ② 씬 무접촉 ③ 상대 소유 파일 무접촉**이다. 편의를 위해 이 셋을 우회하는 판단은 어떤 경우에도 하지 말고, 필요하면 §7 의 요청서 경로를 쓴다.
> 6. **이 §0 규약 블록 자체는 수정 금지.**

## §1. 이 브랜치의 범위 (v2)

> **v2 개정 이유**: 전술 명령·집결지 같은 UI 기능은 결국 **AI 거동을 바꾸는 것**이라, UI와 AI가 다른 PC에 갈라져 있으면 어느 쪽도 결과를 확인할 수 없다. 유저 결정으로 **전투 AI는 UI 브랜치(다른 PC)로 이관**됐다. 이 브랜치는 **건설 · 웨이브 · 맵 · 몬스터 정의**에 집중한다.

### 맡는 것 (PROTO)
| 영역 | 내용 |
|---|---|
| **건설(포탑)** | `Scripts/Build/**`(신규). `DamageableUnit` 상속 + `UnitKind.Tower`. 배치 판정은 `MapGenerator.RegisterStructureFootprint`(진행상황 14절) 재사용. **포탑 원본은 씬 오브젝트가 아니라 프리팹**(§3) |
| **웨이브 규칙·구성표** | `Scripts/Wave/**`, 신규 `WaveDefinitionSO`. 10웨이브 1사이클, 5=중간보스 / 10=메인보스, 정비시간 초과 광폭화, 보스 전용 사이클 배율(진행상황 4절 미결 7번), 웨이브 종료 후 잔존 몬스터 정리 |
| **몬스터 정의·스폰** | `MonsterUnit`, `MonsterDefinitionSO`, `MonsterSpawner`, `NeutralMonster*` 3종 + `Data/Units/Monster_*.asset` |
| **맵 생성 / 타일 / 안개** | `Scripts/Map/**`, `Scripts/Fog/**`, `Data/Map/**`, `Art/Tiles|OrganicTilemap|Units/**`, `Tools/**`. 맵 크기 vs 몬스터 이동속도 문제(진행상황 3절)도 여기 |

### 맡지 않는 것 (건드리면 머지가 깨진다)
| 영역 | 이유 |
|---|---|
| **`Assets/Scenes/Proto_01.unity`** | **UI 브랜치 단독 소유. 열어서 저장 금지** (§3) |
| **전투 AI** `UnitCombat`, `UnitRegistry`, `DamageableUnit`, `CharacterBehavior` | UI 브랜치가 UI와 붙여서 개발 중 |
| **캐릭터** `CharacterUnit`, `UnitSpawner`, `CharacterUpgradeService`, `Nexus` | UI |
| **자원** `ResourceManager` | **이미 구현되어 있다. 다시 만들지 말 것** — §9 |
| **전투 밸런스 공식·수치** `BalanceConfigSO.cs`, `BalanceConfig.asset` | UI |
| **HUD 전반** `Scripts/UI/**` | UI |

> ⚠️ **경계 주의**: 몬스터의 *정의·스폰·구성*은 이 브랜치, 몬스터의 *전투 거동*(`UnitCombat`)은 UI 브랜치다. 웨이브 구성을 바꾸다가 전투 FSM 을 고치고 싶어지면 **§7 의 API 요청서**로 넘길 것.

**건설 UI 는 예외적으로 허용한다**: 배치 고스트·건물 선택 같은 **디버그 수준 최소 UI**. 단
- 파일은 반드시 `Assets/_Project/Scripts/Build/` 아래 (`Scripts/UI/` 는 UI 소유 — 절대 금지)
- 클래스명에 `Debug` 또는 `Proto` 를 붙여 임시임을 드러낼 것 (예: `TowerPlacementProtoUI`)
- **씬에 UI 오브젝트를 만들지 말 것** — 코드로 런타임 생성하거나(UI 브랜치의 `HudBootstrap` 방식 참고) 씬반영요청(§7)으로
- 정식 HUD 편입은 머지 후 UI 브랜치가 담당. 예쁘게 만드는 데 시간 쓰지 말 것

## §3. 씬 규칙 — **PROTO 는 씬을 열지 않는다**

### ⚠️ `Assets/Scenes/Proto_01.unity` 는 **38 MB 텍스트 YAML 파일**이다
320×320 타일맵이 씬에 직렬화되어 있다. 충돌하면 손으로 병합할 방법이 없고 한쪽 작업을 통째로 버려야 한다.
**v2 에서 씬 소유권은 UI 브랜치로 넘어갔다** — 전투 AI가 그쪽으로 가면서 `Character_Template` 인스펙터를 반복 조정하게 됐기 때문이다. 이 브랜치가 씬을 전혀 건드리지 않으면 **이 파일에 충돌이 날 수 없다.**

| 규칙 | 내용 |
|---|---|
| **P-S1** | **`Proto_01.unity` 를 저장하지 말 것.** Unity 에서 열어 실행(Play)해보는 것은 괜찮지만, **오브젝트를 추가·삭제·이동하지 말고 Ctrl+S 를 누르지 말 것.** 실수로 저장했으면 즉시 `git checkout -- Assets/Scenes/Proto_01.unity` 로 되돌린다. |
| **P-S2** | **커밋 직전 반드시 `git status` 로 `Proto_01.unity` 가 딸려오는지 눈으로 확인할 것.** Unity 가 자동 저장하는 경우가 있다. |
| **P-S3** | **맵 재생성 금지.** 재생성은 38MB 씬 전면 재작성이다. 맵 파라미터(`MapGenConfig.asset`)는 고쳐도 되지만 **생성 버튼을 누르지 말 것** — 재생성이 필요하면 §7 의 씬반영요청으로 UI 쪽에 넘긴다. |
| **P-S4** | **포탑 원본(`Tower_Template`)은 씬 오브젝트가 아니라 프리팹으로 만든다** — `Assets/_Project/Prefabs/Build/Tower_Template.prefab`. `Instantiate` 는 씬 오브젝트와 프리팹을 모두 받으므로 기존 템플릿 복제 패턴(진행상황 5절)이 그대로 통한다. 스포너/매니저가 프리팹을 직접 참조하면 씬을 건드릴 이유가 없다. |
| **P-S5** | 매니저류 루트 오브젝트(`BuildManager` 등)가 필요하면 **씬에 넣지 말고** `[RuntimeInitializeOnLoadMethod]` 로 런타임 생성하거나(UI 브랜치의 `HudBootstrap` 이 그 방식이다) §7 의 씬반영요청으로 UI 에 넘긴다. |
| **P-S6** | 새 씬을 만들지 말 것. |
| **P-S7** | 씬에 손대야만 하는 일(템플릿 인스펙터 값 변경, `WaveManager` 에 `WaveDefinitionSO` 연결 등)은 전부 §7 의 **씬반영요청_PROTO→UI.md** 로 넘긴다. |

## §6. git 규율 — 22절 사고를 반복하지 않기 위한 것

> 2026-08-05, 커밋하지 않은 작업(스크립트 6개 + SO 3개 + 씬 변경)이 **브랜치 전환/discard 로 통째로 사라졌다.** 대화 맥락이 남아있어 겨우 복구했다 (진행상황 22절 마지막).

| 규칙 | 내용 |
|---|---|
| **P-G1** | **브랜치는 `PROTO` 하나만 쓴다.** `main` 과 `UI` 는 **체크아웃조차 하지 말 것.** 원격을 보려면 `git log origin/main` 처럼 참조만 읽는다. |
| **P-G2** | **작업 단위마다 즉시 커밋.** "나중에 한 번에" 는 금지. |
| **P-G3** | **하루 1회 이상 `git push origin PROTO`.** 푸시 안 한 작업은 이 PC가 죽으면 없어지고 유저가 진행상황을 볼 수도 없다. |
| **P-G4** | 커밋 메시지: `[PROTO][ADD\|MOD\|FIX] 한 줄 요약`. |
| **P-G5** | `git reset --hard` / `git checkout -- .` / IDE의 "모든 변경사항 취소" **금지.** 되돌리고 싶으면 유저에게 물어볼 것. 단 하나의 예외: 실수로 `Proto_01.unity` 를 저장했을 때 그 **한 파일만** `git checkout -- Assets/Scenes/Proto_01.unity`. |

## §7. UI 브랜치에 요청하는 방법

상대 소유 파일과 **씬**이 필요하면 **직접 고치지 않고** 요청서에 적는다. 커밋·푸시한 뒤 **유저에게 구두로도 알릴 것.**

### `Docs/인계/씬반영요청_PROTO→UI.md` — 씬에 넣어야 하는 것 (자주 쓰게 된다)
```markdown
## 요청 N — <한 줄 제목>
- 날짜:
- 요청 내용: (예: BuildManager 루트 오브젝트 추가 + Tower_Template.prefab 참조 연결)
- 왜 씬이어야 하는가: (런타임 생성이나 프리팹으로 못 하는 이유 — 대안을 먼저 검토했음을 보일 것)
- 필요한 값: (컴포넌트별 인스펙터 값까지 구체적으로)
- 시점: 머지 전에 필요 / 머지 후에 해도 됨
- 상태: 요청 / 유저 확인 / 반영됨(커밋 해시)
```
> **먼저 §3 P-S4·P-S5 를 검토할 것.** 포탑 원본은 프리팹으로, 매니저는 런타임 생성으로 대부분 해결된다. 씬반영요청은 그게 안 될 때만.

### `Docs/인계/API요청_PROTO→UI.md` — UI 소유 클래스에 필요한 공개 API
```markdown
## 요청 N — <한 줄 제목>
- 날짜:
- 필요한 것: (클래스 · 제안 시그니처)
- 왜 필요한가:
- 임시 대응: (반영 전까지 PROTO 가 어떻게 버티는지)
- 상태: 요청 / 유저 확인 / 반영됨(커밋 해시)
```
- **추가만 요청한다.** 기존 시그니처 변경·삭제는 요청 대상이 아니다(양쪽 컴파일이 깨진다).
- 전투 FSM 자체를 바꾸는 요청은 UI 브랜치의 설계 판단 영역이다 — **무엇이 필요한지**를 적고 **어떻게 고칠지**는 맡길 것.

## §9. ⚠️ 진행상황.md 요약 표가 낡았다 — 반드시 읽을 것

`진행상황.md` 15절의 **문서 유실 사고(15~19절 결번)** 때문에 상단 "지금까지 만든 것" 요약 표가 **실제 코드와 맞지 않는다.** 표에 "❌ 미착수"로 적힌 것 중 아래는 **이미 구현되어 있다.** 다시 만들면 머지에서 정면충돌한다.

| 표 표기 | 실제 | 파일 |
|---|---|---|
| 자원 시스템 ❌ | ✅ **구현됨** — 에너지 풀, 몬스터 처치 획득, `TrySpend`/`CanAfford` | `Scripts/Resource/ResourceManager.cs` (**UI 소유**) |
| 캐릭터 성장/생성 UI ❌ | ✅ **강화 구현됨** — 캐릭터별 누진 비용, 4스탯 랜덤 성장 | `Scripts/Units/CharacterUpgradeService.cs` (**UI 소유**) |
| UI 전반 ❌ | ⚠️ **부분 구현** + UI 브랜치가 지금 HUD 전면 작업 중 | `Scripts/UI/**` (**UI 소유**) |
| (표에 없음) | ✅ 격자 경로탐색 | `Scripts/Map/GridPathfinder.cs` (PROTO 소유) |
| (표에 없음) | ✅ 유기적 타일셋 + 임포터 | `Scripts/Map/OrganicTileSetSO.cs`, `Editor/OrganicTileSetImporter.cs` (PROTO 소유) |
| (표에 없음) | ✅ 한글 픽셀 폰트 SDF | `Resources/Fonts/NeoDunggeunmo SDF.asset` (**UI 소유**) |

**즉 15~19절의 잃어버린 내용은 "자원 시스템 + 캐릭터 강화 + 유닛 선택 + 최소 UI + 유기적 타일셋 + 경로탐색 + 한글 폰트"였던 것으로 추정된다.** 코드는 남아있고 문서만 없다.
→ **작업 전에 해당 파일들을 직접 읽을 것. 문서가 아니라 코드가 사실이다.**

여전히 **정말로 미착수**인 것 (= 이 브랜치가 만들 것): **건설(포탑)**, `WaveDefinitionSO`(웨이브별 구성), 보스 전용 사이클 배율, 정비시간 초과 광폭화, 웨이브 종료 후 잔존 몬스터 정리.
