# 공개 API 요청 — UI → PROTO

> UI 브랜치가 PROTO 소유 클래스(`Scripts/Combat|Units|Map|Fog|Wave|Build|Resource/`)에 없는 공개 API 가 필요할 때 쓴다.
> **직접 고치지 말 것** — 상대 소유 파일을 만지면 머지가 깨진다 (`UI 브렌치 준수사항.md` §2).
>
> 현재 쓸 수 있는 API 목록은 준수사항 §5 U-D4 에 있다. **먼저 그 목록을 확인할 것** — 대부분 이미 있다.
>
> **작성**: UI 브랜치만 · **처리**: PROTO 브랜치. 이 파일은 UI 소유이고 PROTO 는 `상태` 칸만 갱신한다.

---

## 양식 (복사해서 쓸 것)

```markdown
## 요청 N — <한 줄 제목>
- 날짜:
- 필요한 것: (클래스 · 시그니처 제안)
- 왜 필요한가:
- 임시 대응: (반영되기 전까지 UI 가 어떻게 버티는지 — 보통 "해당 표시를 잠시 끈다")
- 상태: 요청 / 유저 확인 / 반영됨(커밋 해시)
```

### 요청을 쓸 때 지킬 것
- **추가만 요청한다.** 기존 API 의 시그니처 변경·삭제는 요청 대상이 아니다 (양쪽 컴파일이 깨진다).
- **읽기 전용 getter 를 우선 요청한다.** 상태를 바꾸는 메서드는 AI 로직의 책임 범위이므로 PROTO 가 설계해야 한다.
- 반영 전까지 **UI 가 동작 불가가 되지 않도록** 임시 대응을 반드시 적는다.
