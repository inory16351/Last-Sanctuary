# 공개 API · 계약 변경 요청 — PROTO → UI

> PROTO 브랜치가 UI 소유 클래스(`Scripts/UI/`)나 **동결된 계약 파일**(`Scripts/Orders/`)에 변경이 필요할 때 쓴다.
> **직접 고치지 말 것** — 특히 `Scripts/Orders/` 는 양쪽 모두 수정 금지다 (`프로토 브렌치 준수사항.md` §4).
>
> **작성**: PROTO 브랜치만 · **처리**: 유저가 `main` 에 반영 → 양쪽이 `git merge origin/main` 으로 받아간다
> 계약 변경은 **한쪽만 반영하면 반드시 깨지므로** 반드시 유저를 경유한다.

---

## 양식 (복사해서 쓸 것)

```markdown
## 요청 N — <한 줄 제목>
- 날짜:
- 종류: 계약 변경(Scripts/Orders) / UI 클래스 API / 기타
- 필요한 것: (제안 시그니처 또는 추가할 enum 값)
- 왜 필요한가: (AI 로직이 무엇을 표현할 수 없는지)
- 임시 대응: (반영 전까지 PROTO 가 어떻게 버티는지)
- 영향: (UI 쪽에서 같이 고쳐야 하는 것 — 드롭다운 항목, 툴팁 문구 등)
- 상태: 요청 / 유저 확인 / main 반영됨(커밋 해시) / 양쪽 merge 완료
```

### 계약 변경 요청을 쓸 때 지킬 것
- **enum 값 하나를 늘리는 것도 계약 변경이다.** PROTO 의 `switch` 와 UI 의 드롭다운이 동시에 바뀌어야 한다.
- 계약이 없어도 **기본값(`CharacterOrders.Default`)으로 지금과 똑같이 동작해야 한다**는 규칙(P-C2)을 어기는 요청은 하지 말 것.
- 명령값의 **의미 해석**은 요청 대상이 아니다 — PROTO 가 정하고 `작업로그_PROTO.md` 에 적으면 UI 툴팁이 따라온다 (P-C5).
