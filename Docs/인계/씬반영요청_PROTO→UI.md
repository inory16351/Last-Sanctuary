# 씬 반영 요청 — PROTO → UI

> `Assets/Scenes/Proto_01.unity` 는 **UI 브랜치 단독 소유**다 (38MB, 충돌 시 복구 불가 — `프로토 브렌치 준수사항.md` §3).
> PROTO 브랜치가 씬에 무언가 필요하면 **직접 열어 저장하지 말고** 이 파일에 적고 유저에게 구두로도 알린다.
>
> **작성**: PROTO 브랜치 · **처리**: UI 브랜치 (또는 머지 담당자)
> UI 는 처리 후 `상태` 칸에 커밋 해시를 남긴다. 처리된 요청도 **지우지 말 것.**

---

## ⚠️ 요청서를 쓰기 전에 — 대부분은 씬 없이 해결된다

| 하고 싶은 것 | 씬 없이 하는 방법 |
|---|---|
| 포탑 원본(`Tower_Template`) 배치 | **프리팹으로 만든다** — `Assets/_Project/Prefabs/Build/Tower_Template.prefab`. `Instantiate` 는 프리팹도 받으므로 기존 템플릿 복제 패턴(진행상황 5절)이 그대로 통한다 (P-S4) |
| `BuildManager` 같은 매니저 오브젝트 | **`[RuntimeInitializeOnLoadMethod]` 로 런타임 생성** — UI 브랜치의 `HudBootstrap` 이 같은 방식이다 (P-S5) |
| 밸런스·정의 값 변경 | SO 에셋(`Data/Units/**`, `Data/Map/**`)은 PROTO 소유다. 그냥 고치면 된다 |
| 맵 파라미터 변경 | `MapGenConfig.asset` 은 고쳐도 된다. **다만 생성 버튼은 누르지 말 것** — 재생성은 씬 재작성이다 (P-S3) |

**위 방법으로 안 되는 것만** 아래에 적는다. "왜 씬이어야 하는가" 칸에 대안을 검토했음을 보일 것.

---

## 양식 (복사해서 쓸 것)

```markdown
## 요청 N — <한 줄 제목>
- 날짜:
- 요청 내용: (씬에 무엇을 어떻게)
- 왜 씬이어야 하는가: (위 표의 대안을 왜 못 쓰는지)
- 필요한 값: (컴포넌트별 인스펙터 값까지 구체적으로. UI 가 그대로 넣을 수 있어야 한다)
- 시점: 머지 전에 필요 / 머지 후에 해도 됨
- 상태: 요청 / 유저 확인 / 반영됨(커밋 해시)
```
