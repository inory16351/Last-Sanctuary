## §1. 전제 — 왜 이 계획이 필요한가

| 사실 | 결과 |
|---|---|
| `Assets/Scenes/Proto_01.unity` = **38,079,617 byte (38MB) 텍스트 YAML**. 320×320 타일맵이 씬에 직렬화되어 있다 | 이 파일이 충돌하면 **손으로 병합 불가**. 한쪽을 통째로 버리는 것 외에 방법이 없다 → **씬 단독 소유권**이 계획의 핵심 |
| 저장소는 아직 작다 (packed 3.65 MiB — 씬이 압축이 잘 된다) | 하지만 맵 재생성 커밋마다 새 blob 이 영구히 쌓인다 → **맵 재생성 커밋 최소화** |
| 2026-08-05, **커밋 안 된 작업이 브랜치 전환/discard 로 통째로 사라진 사고**가 있었다 (진행상황 22절) | **단위별 즉시 커밋 + 매일 푸시**가 규칙 |
| `진행상황.md` 1~19절이 유실된 사고가 있었다 (진행상황 15절). 이 문서는 git 밖 Obsidian 볼트에 있고 백업이 없다 | 시드 커밋에 **읽기 전용 스냅샷**을 git 안에 넣는다 (백업 + 다른 PC 공유 겸용) |
| `진행상황.md` 요약 표가 실제 코드와 어긋나 있다 (자원 시스템·강화·유닛 선택이 이미 구현됨) | 양쪽 준수사항 §9 에 정정 표를 넣었다 — **중복 구현 = 충돌** |
| `UI` 브랜치는 현재 `main` 보다 **1커밋 뒤처져 있고** 고유 커밋이 **0개**, `origin/PROTO` 는 `main` 의 조상(`bb39e53`) | 두 브랜치를 **`main` 의 시드 커밋으로 리셋해도 잃는 것이 없다** |

## §3. 진행 순서

### 단계 0 — 시드 커밋 (병렬 작업 시작 전, `main` 에서 1회) ☐ 미실행
두 브랜치가 **완전히 같은 출발점**을 갖게 만드는 커밋. 여기에 들어갈 것:

| # | 내용 | 이유 |
|---|---|---|
| S1 | `.gitattributes` 신규 — `*.unity binary`, `*.prefab binary` | git 이 38MB 텍스트 머지/diff 를 시도하지 않게 막는 안전장치. 소유권 규칙이 깨졌을 때 쓰레기 병합 결과가 나오는 대신 "양쪽 중 하나를 고르라"고 멈춘다 |
| S2 | `Assets/_Project/Scripts/Orders/TacticalTypes.cs` + `TacticalOrders.cs` (계약, 동결) | 전술 UI 명령의 자료형·접근 경로를 미리 확정. 양쪽이 각자 정의하면 반드시 깨진다 |
| S3 | `UnitSpawner` 에 `public CharacterUnit SpawnOneCharacter()` + `public event Action<CharacterUnit> OnCharacterSpawned` 추가 | 캐릭터 생성 UI가 호출할 유일한 접점. 이걸 미리 넣어두면 UI가 PROTO 소유 파일을 건드릴 이유가 없어진다 |
| S4 | `Docs/` 3개 문서 (`UI 브렌치 준수사항.md`, `프로토 브렌치 준수사항.md`, `머지 계획.md`) | 양쪽 PC가 같은 규약을 읽어야 한다 |
| S5 | `Docs/진행상황_스냅샷_20260805.md` — `진행상황.md` 의 **읽기 전용 사본** | 다른 PC가 전체 맥락을 읽을 수 있게 + git 밖 문서의 백업 (진행상황 8절 9번의 백업 부재 문제 해결) |
| S6 | `Docs/인계/` 폴더 + 요청서 4종 빈 양식 | 요청 경로를 미리 열어둔다 |
| S7 | `.meta` 파일 동반 확인 | **Unity 에디터를 켠 상태에서** 새 `.cs` 를 만들어 `.meta` 가 생성된 뒤 커밋할 것. `.meta` 없이 커밋하면 다른 PC에서 GUID가 새로 발급되어 참조가 어긋난다 |

```bash
# main 에서 (Unity 에디터를 켜서 .meta 생성 확인 후)
git checkout main
git status                                  # clean 확인
git add .gitattributes Assets/_Project/Scripts/Orders Docs
git add Assets/_Project/Scripts/Units/UnitSpawner.cs
git commit -m "[SEED] 브랜치 분업 계약 + 준수사항 문서 + .gitattributes"
git push origin main
```

### 단계 1 — 두 브랜치를 시드 커밋으로 정렬 ☐ 미실행
`UI` 는 고유 커밋 0개, `origin/PROTO`(`bb39e53`)는 `main` 의 조상이므로 **잃는 것이 없다.**
⚠️ `push --force` 는 원격을 되돌리는 작업이다 — **유저 승인 후에만 실행.**

```bash
git branch -f UI main
git push --force-with-lease origin UI

git branch -f PROTO main                    # 로컬 PROTO 가 없으면 새로 생김
git push --force-with-lease origin PROTO

git branch -vv                              # 세 브랜치가 같은 해시인지 확인
```
그다음 다른 PC에서:
```bash
git fetch origin
git checkout -B PROTO origin/PROTO
git log --oneline -1                        # [SEED] 커밋이 보이면 준비 완료
```

### 단계 2 — 병렬 작업
- 각자 자기 브랜치에서만. 준수사항 §2 소유권 준수.
- **`main` 은 이 기간 중 절대 움직이지 않는다** → 정기 동기화(`merge main`)가 필요 없고, 두 브랜치는 시드 커밋에서 갈라진 상태로 각자 전진한다.
- 계약(`Scripts/Orders/`) 변경 요청이 오면 **유저가 `main` 에 반영하고, 두 브랜치가 각자 `git merge origin/main`** 으로 받아간다. 이때만 예외적으로 main 이 움직인다.

### 단계 3 — 머지 전 점검 (양쪽) ☐
§4 체크리스트를 양쪽 모두 통과.

### 단계 4 — 백업 & 태그 (머지 담당자) ☐

```bash
git push origin pre-merge-20260805
```
추가로 **씬 파일을 git 밖에 물리 백업**한다 (38MB, git 되돌리기가 느리므로 즉시 복구용):

### 단계 5 — PROTO 를 먼저 머지 ☐
**순서가 중요하다: PROTO(씬 소유자) → UI.**
씬처럼 큰 변경을 먼저 `main` 에 얹고, 신규 파일 위주인 UI를 그 위에 올리는 것이 충돌 표면이 작다.
```bash

git merge --no-ff origin/PROTO -m "[MERGE] PROTO — AI 로직 · 건설"
# 충돌 시 → §5 처방표
git push origin main
```
머지 직후 **Unity 를 열어 컴파일 에러 0 · 씬 정상 로드**를 확인하고, 문제가 있으면 UI 머지 전에 해결한다.

## §5. 충돌 처방표

> 소유권을 지켰다면 충돌은 아래 3개 파일에서만 날 수 있다. 그 외 파일에서 충돌이 났다면 **소유권 규칙이 깨진 것** — 머지를 중단하고 어느 브랜치가 남의 파일을 만졌는지 확인한 뒤 유저에게 보고할 것.

| 파일 | 처방 |
|---|---|
| `Assets/Scenes/Proto_01.unity` | **충돌하면 안 되는 파일.** `.gitattributes` 의 `binary` 때문에 자동 병합은 시도되지 않고 "both modified" 로 멈춘다. → 머지를 **중단**(`git merge --abort`)하고, UI 쪽이 왜 이 파일을 커밋했는지 확인. UI 쪽 변경이 실수라면 UI 브랜치에서 그 파일만 되돌린 뒤(`git checkout origin/main -- Assets/Scenes/Proto_01.unity` → 커밋) 다시 머지. **절대 눈대중으로 한쪽을 고르지 말 것** — 어느 쪽 작업이 사라지는지 알 수 없다 |
| `Docs/*.md` | 텍스트 충돌. **양쪽 내용을 모두 살려서 수동 병합**한다. 준수사항 문서는 각자 소유이므로 충돌 시 그 문서의 소유 브랜치 쪽을 기준으로 하고, 상대가 추가한 내용은 §갱신 이력에 남긴다 |
| `ProjectSettings/EditorBuildSettings.asset` | 작은 텍스트 파일. **양쪽 씬 목록을 모두 남기도록 수동 병합** (`Proto_01` + `UI_HUD` 둘 다 존재해야 한다) |
| `Assets/_Project/Scripts/Orders/**` | 동결 파일이므로 충돌 = 규칙 위반. 머지 중단 → 유저 판단 |
| `*.meta` | 충돌 시 **GUID 를 임의로 고르지 말 것.** 원래 `main` 에 있던 파일이면 `main` 쪽 GUID를 유지한다(씬 참조가 그걸 가리킨다). 신규 파일이면 만든 브랜치 쪽 GUID |
| 같은 이름의 신규 `.cs` / `.asset` 을 양쪽이 만든 경우 | 파일명 규칙(§2)을 어긴 결과. 하나를 개명하고 **양쪽 참조를 모두 수정**해야 한다 — 씬 참조까지 확인할 것 |

### 머지가 잘못됐을 때 롤백
```bash
git merge --abort                          # 머지 진행 중이라면
git reset --hard pre-merge-20260805        # 이미 커밋했다면 (push 전)
# 이미 push 했다면 되돌림 커밋을 만든다 (히스토리 재작성 금지)
git revert -m 1 <머지커밋해시>
```
씬이 이상해졌으면 단계 4의 물리 백업을 덮어쓴다 (git 되돌리기보다 빠르다).
